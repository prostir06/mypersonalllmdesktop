# v15 Wave 2 — Targeted Debt / Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add soft lint guards and refresh npm audit hygiene without major refactors or Prisma/SheetJS force upgrades.

**Architecture:** Extend existing flat ESLint configs (`backend/eslint.config.mjs`, `frontend/eslint.config.mjs`) with warning-level `max-lines` and `no-empty`. Run non-breaking `npm audit fix` in backend/frontend and update `docs/security-audit-baseline.md` + `backend/scripts/audit-ci.cjs` allowlist if GHSA set changes. No service splits unless a file fails soft rules **and** is already being touched for lint baseline — prefer documenting baseline overrides over drive-by refactors.

**Tech Stack:** ESLint flat config, `npm audit` / `audit:ci`, Jest/Vitest (regression only).

**Spec:** `docs/superpowers/specs/2026-10-27-project-evolution-roadmap-v15-design.md` §5  
**Prerequisite:** Wave 1 gate green on `master`.

## Global Constraints

- Soft rules = **warn**, not error (do not fail CI on existing large files).
- No Prisma major rewrite, no `npm audit fix --force`, no xlsx replacement.
- No Redis/BullMQ; no H1–H5 infra from performance roadmap.
- Do not split large test files.
- Touch at most 1–2 production source files for line-count — only if unavoidable; prefer warn + ignore pattern for `__tests__` (already ignored in backend).

### Task 1: Soft ESLint backend

**Files:**
- Modify: `backend/eslint.config.mjs`
- Verify: `backend/package.json` script `lint`

**Interfaces:**
- Produces: warnings for `max-lines` and `no-empty` on `src/**/*.ts` (tests already ignored)

- [ ] **Step 1: Add rules**

In `backend/eslint.config.mjs` `rules` object, add:

```js

        'warn',
```
