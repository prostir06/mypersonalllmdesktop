# Product Tour (Інтерактивний гід додатком) — Design Specification

**Дата:** 2026-11-03  
**Версія туру:** `v18.1`  
**Статус:** Реалізовано (версія туру `v18.1`)  
**Призначення:** Інтерактивний онбординг для нових користувачів та швидке знайомство з новими можливостями платформи (мультипровайдерність, автономні інструменти, універсальний вебпошук, артефакти, пам'ять).

---

## 1. Цілі та вимоги

### 1.1. Бізнес-цілі
- Забезпечити швидке та зрозуміле знайомство нових користувачів із ключовими елементами інтерфейсу.
- Автоматично інформувати існуючих користувачів про нові додані можливості завдяки системі версіонування туру.
- Надати можливість у будь-який момент вручну перезапустити тур з верхньої панелі навігації.

### 1.2. Технічні та архітектурні обмеження
- **Zero external dependencies:** легковаговий нативний React-компонент без сторонніх важких бібліотек (як `react-joyride`), щоб утримати бандл у межах ліміту 180 КБ.
- **Відповідність стилю додатку:** темна палітра, `glass-panel`, неонові акценти, підтримка української мови.
- **Стійкість (Resilience):** якщо цільовий елемент не знайдено або він поза межами видимості, тур не падає, а плавно позиціонує підказку або переходить до наступного кроку.

## 2. Модель даних та конфігурація

### 2.1. Типізація кроків (`frontend/src/types/tour.ts`)
```ts
export type TourPlacement = 'top' | 'bottom' | 'left' | 'right' | 'center';

export interface TourStep {
  id: string;
  target: string; // CSS-селектор або data-tour атрибут
  title: string;
  content: string;
  placement?: TourPlacement;
  isNew?: boolean; // Позначка «Новинка!»
  actionBefore?: () => void;
}

export interface TourState {
  isActive: boolean;
  currentStepIndex: number;
  hasNewVersion: boolean;
}
```

## 3. Керування станом та версіонування

### 3.1. Логіка сховища (`localStorage`)
- Ключ: `product_tour_completed_version`
- Поточна версія конфігурації: `CURRENT_TOUR_VERSION = 'v18.1'`
- **Правило запуску:**
  - Якщо в `localStorage` ключ відсутній → автоматичний запуск для нового користувача при першому вході на Dashboard.
  - Якщо збережена версія `< CURRENT_TOUR_VERSION` → біля кнопки туру у навігації з'являється індикатор `NEW` (є нові функції для ознайомлення).
  - При завершенні або натисканні «Пропустити» → записується `localStorage.setItem('product_tour_completed_version', CURRENT_TOUR_VERSION)`.

## 4. Компоненти інтерфейсу

### 4.1. `ProductTour.tsx`
- Монтується через `ReactDOM.createPortal(..., document.body)`.
- **Spotlight Backdrop:**
  - Напівпрозорий шар `rgba(0,0,0,0.65)` із підсвіткою активного прямокутника цільового елемента.
  - Анімований перехід координат при зміні кроку.
- **Popover Card:**
  - Лічильник кроків (наприклад, `Крок 3 з 6`).
  - Бейдж `✨ Новинка` (за наявності `isNew: true`).
  - Кнопка закриття `✕`.
  - Кнопки: «Пропустити», «Назад», «Далі» / «Завершити».
  - Позиціонування з авто-корекцією меж вікна.

### 4.2. Навігація в `Navbar.tsx`
- Додається кнопка `🧭 Тур додатком` (tooltip: *«Інтерактивний гід можливостями додатку»*).
- За наявності нових непереглянутих версій — бейдж `NEW`.

## 5. Тестування та верифікація
1. **Unit-тести на Vitest (`ProductTour.test.tsx`):**
   - Автоматичний старт, якщо версія не збережена.
   - Збереження поточної версії в `localStorage` при закритті/пропуску.
   - Переходи Next / Prev / Escape / клавіші стрілок.
   - Стійкість до відсутніх DOM-елементів (graceful fallback).
2. **Інтеграційні тести в `Navbar` / `Dashboard`:**
   - Кнопка ручного запуску туру працює належним чином.
   - Атрибути `data-tour` присутні на ключових елементах.
